# Владение системой NETRUN

Актуальная граница задачи, согласованная 3 ноября 2026 года: **Core полностью владеет NETRUN**.
Это относится ко всему состоянию системы и её правилам, а не только к сетевой математике.

## Граница Core и DM

| Подсистема | Единственный владелец состояния и правил |
| --- | --- |
| Топология, LAN/APC-привязки, маршруты, доставка, discovery | Core |
| Сетевые доступы, grants, ключи, credentials, отзыв прав, gate policy | Core |
| Сущности, ICE, боты, цели, планирование, фракции, персона | Core |
| Бой, очередь участников, AP, cooldown, касты и статусы | Core |
| Сетевые файлы, хранилища, содержимое, вместимость, копирование и перенос | Core |
| Сетевые объекты, их создание, изменение и удаление | Core |
| Выполнение задач NETRUN и их FIFO-порядок | Core |
| Расширения/моды и их состояние | Core, через публичные контракты расширения |
| Физические объекты BYOND, моб-представление, тело, органы, зрение и звук | Native DM adapters |
| Отображение интерфейса | DM/TGUI по проекциям Core |

DM публикует исходные факты физического мира, передаёт намерения и принимает обратные события.
Он не вычисляет топологию, effective network access, пути, тактику, ёмкость дисков или результаты
сетевых операций. Проекция в DM не становится вторым mutable владельцем доменной модели.

Native adapter проверяет, что физический объект того же поколения ещё существует и факты,
на которых основано действие Core, не изменились. При изменении он сообщает отказ и новые факты.
Он не пересчитывает решение Core самостоятельно. Физические игровые эффекты выполняются штатными
BYOND API в игровом потоке; Core не хранит native references и не вызывает DM procs напрямую.

## Асинхронный контракт

```text
DM → enqueue фактов/намерения → продолжение игрового процесса
Core → FIFO dispatch → domain state/projection либо native effect
DM → native effect → отдельный outcome/fact в Core
```

ACK входного кадра, admission задачи, окончание вычисления и результат native действия — разные
события. Ожидание ответа не блокирует игровой поток и не держит head очереди Core. Native outcome
поступает новой задачей в хвост FIFO. Неизвестный исход одноразового действия не повторяется автоматически.

Входные задачи принимаются и запускаются в общем FIFO-порядке. Длительное вычисление сохраняет
cooperative continuation своего head; бюджет Pump ограничивает выполненную работу. Промежуточная
публикация не позволяет следующей задаче обогнать незавершённые обязательные domain effects.
Выходной транспорт может обслуживать разные подписки независимо; domain revisions и task sequence
позволяют отвергать старые проекции и отличать completion от фактического применения native эффекта.

У DM остаются транспортные буферы и помпы доставки обратных событий. Собственный NETRUN scheduler
для выбора/исполнения simulation-задач должен исчезнуть после перевода всех его потребителей.

## Расширения

Доверенные локальные DLL подключаются явным списком. Они могут вносить стратегии, нормализаторы
фактов и stateful модули. Каждому binding принадлежит отдельная mod session. Cooperative задачи модов
исполняет общая FIFO-очередь; immutable projections и типизированные effects проходят те же owners,
что штатная механика. API не передаёт расширениям native объекты или имена исполняемых DM procs.

Состав проверяется до первого input: API version, уникальные identifiers, закрытие registry после
Configure и откат ресурсов при неуспешной загрузке. JSONL-логи/телеметрия используют binding/request/task
идентификаторы без payload, credentials и ключей. См. [plugins.md](plugins.md), [logging.md](logging.md).

## Текущее состояние переноса

Существующая topology/transport миграция сохранена. Добавлены actor registry, raw access authority,
bounded navigation, общая FIFO, mod sessions, pure combat/bot/storage owners и wire/runtime точки
интеграции. Их наличие само по себе **не означает завершённого переключения станции**.

DM entity bridge пока подключается явно. В production ещё остаются прежние brains, combat/navigation,
file/storage facades с собственными правилами и scheduler. Их нельзя объявлять удалёнными либо
отключать до сквозного подключения Core owners, восстановления состояния и проверки parity.

Для полного завершения остаётся связать бот/ICE orchestration, inventory/executable consumption,
breach/remote combat contacts, spawn/death/loot и восстановление после потери binding; перенести
оставшиеся network objects/security/content rules и UI read models; заменить все DM simulation
вызовы и удалить scheduler после обнуления его production consumers. Сквозная проверка должна
включать настоящую DM/bridge/Host пару, повторное подключение, удаление/переиспользование объектов,
отзыв доступа, burst/backpressure и длительную нагрузку на полной карте.

Подробности текущего adapter seam: [entity-migration.md](entity-migration.md).
