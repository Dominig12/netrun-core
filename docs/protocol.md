# Протокол разработки v1.0: подмножество mirror

Это спецификация узлового подмножества 1.0 автономного стенда. Новые controls
и стадии 1.1 описаны в [синхронизации](synchronization.md). Codec читает minor 0/1;
sync controls требуют minor 1, обычные узловые пакеты принимаются в обоих.
Полный v1 из
проектного документа ещё не реализован и не обещает совместимости с этим
подмножеством. До подключения DM будет нужен отдельный review схемы и negotiation.

## Framing

Четыре байта unsigned длины тела в network byte order, затем ровно столько
байтов UTF-8 JSON. Длина тела: 1..1048576 байтов, проверяется до выделения тела.
Частичные чтения и несколько последовательных кадров поддерживаются. EOF до
первого байта header завершает поток; EOF посреди header/body — `frame_truncated`.
Чтение/запись принимает CancellationToken. Владение потоком остаётся у вызывающего.

JSONL применяется только для удобства offline fixtures: один полный кадр JSON
на строку, LF/CRLF, последняя строка может быть без LF. Пустые строки недопустимы;
лимит применяется к телу без CRLF. Это не формат будущего сетевого IPC.

## Вход

В каждом объекте обязательны **все и только** перечисленные поля; дубли полей,
неизвестные поля, null, несовместимые типы и неизвестные изменяющие kinds отвергаются.
Глубина JSON ограничена 32; некорректный UTF-8/Unicode не заменяется незаметно.

| Поле | Тип и правило |
|---|---|
| `protocol_major`, `protocol_minor` | JSON integer: `1`, `0` для исходного узлового подмножества; `1`, `1` для sync |
| `world_epoch`, `engine_epoch`, `binding_epoch` | Непустые строки до 128 UTF-16 code units |
| `sequence` | Строковый положительный ulong, первый новый пакет — `"1"` |
| `simulation_time_ds` | JSON integer 0..2147483647, монотонные децисекунды мира |
| `entries` | Упорядоченный массив 0..128 записей |

Все текстовые поля запрещают управляющие символы и whitespace-only строки.
Счётчики кодируются канонически: `[1-9][0-9]*`, не больше `18446744073709551615`.
Числовое JSON-представление, ведущий ноль, пробел, знак или экспонента недопустимы.

`node_upsert`:

```json
{
  "kind": "node_upsert",
  "node_id": "node-1",
  "generation": "1",
  "node_revision": "2",
  "state": {
    "address": "APC-1",
    "node_type": "apc",
    "position": { "x": 10, "y": 20, "z": 1 },
    "sector_id": "sector:1",
    "online": true
  }
}
```

`node_id` — до 128 UTF-16 code units; остальные текстовые поля state — до 256.
`generation` и `node_revision` — положительные строковые ulong.
`x`, `y` — integers 1..32767, `z` — 1..4096; `online` — boolean.
State заменяется целиком. XYZ и sector_id пока не составляют полный топологический
контракт: нужны base-area identity и связность/порядок этажей.

`node_remove` содержит только `kind`, `node_id`, `generation`, `node_revision`.
Удаление неизвестного ID также создаёт tombstone. Внутри поколения меньшая версия
игнорируется; равная допустима только с тем же полным фактом/удалением. После
удаления новые upsert того же поколения отвергаются, даже при большей версии.
Большее поколение может начать revision заново; меньшее поколение игнорируется.

## Применение и повторы

Весь пакет проверяется и stage-ится до публикации. Записи видят предыдущие записи
того же пакета. Валидационный отказ оставляет mirror, время и ACK прежними.
Повтор версии узла и повтор целого пакета — разные уровни проверки.

Хранятся fingerprints последних 64 применённых пакетов. Содержательно одинаковый
повтор возвращает `duplicate` и текущий cumulative ACK. Несовпадающий либо
вытесненный replay, а также gap, закрывает сессию в `resync_required`.
После этого новые входы не применяются. Нельзя обходить барьер отправкой
пропущенного пакета: нужен новый mirror/binding после будущего полного resync.
Epoch mismatch отвергается без изменения текущей сессии.

Лимит mirror — 10000 различных ID, включая tombstones. При capacity отказе
не применяется ни одна запись. Локальный C#-конструктор позволяет настроить
CoreLimits; handshake и согласования лимитов с DM пока нет.

## Выход стенда

Каждый разобранный вход получает `apply_result` с полями `output_sequence`
(строка), `status`, `code`, `applied_sequence` (строка), `simulation_time_ds`,
`node_count`, `tracked_count`. При protocol error кадр результата не создаётся;
в stderr выводится только безопасный код и процесс завершает работу с кодом 2.

Статусы: `applied`, `duplicate`, `rejected`, `resync_required`. Output sequence
пока служит диагностике: нет выходного журнала, ACK от DM или гарантии доставки.
Не использовать такой результат как разрешение на игровые эффекты.

Основные safe-коды parser: `frame_size`, `frame_truncated`, `invalid_utf8`,
`invalid_json`, `schema_invalid`, `protocol_version`, `entry_kind`.
Коды mirror: `epoch_mismatch`, `invalid_batch`, `unsupported_change`,
`sequence_gap`, `time_regression`, `revision_conflict`, `generation_retired`,
`mirror_capacity`, `replay_conflict_or_expired`, `resync_required`.
